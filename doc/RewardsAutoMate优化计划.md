# RewardAutoMate 优化计划

> 版本：v1.0  
> 日期：2026-06-08  
> 基于：《需求文档.md》+《RewardsAutoMate代码分析报告.md》

---

## 一、项目现状

### 1.1 现有能力
- Bing PC/Mobile 搜索自动化（固定 50 次）
- 热力图可视化 + SQLite 历史记录
- 每 12 小时定时执行
- 系统托盘最小化

### 1.2 核心短板
- **与 Rewards Dashboard 零交互** — 无法感知任务状态、无法领取积分
- **架构僵化** — 所有业务硬编码在 219 行的静态类中
- **配置缺失** — 搜索次数、间隔、定时全部写死
- **黑盒依赖** — `BaseTool.dll`、`BaseWPFControl.dll` 源码不可控
- **完成度仅 ~15%**

---

## 二、优化目标

| 目标 | 衡量标准 | 优先级 |
|------|---------|--------|
| **接入 Rewards Dashboard** | 能读取积分、等级、任务状态 | P0 |
| **自动领取积分** | 检测"可领取"并一键领取 | P0 |
| **Daily Set 自动化** | 每日 3 项任务自动完成 | P0 |
| **福利奖励领取** | Star/升级/搜索奖励自动领取 | P0 |
| **搜索次数动态化** | 根据 Dashboard 进度调整，非固定 50 次 | P0 |
| **任务处理器体系** | 新任务类型可插拔扩展 | P1 |
| **配置系统** | 所有参数外部可配置 | P1 |
| **日志体系替换** | 移除黑盒 `BaseLogManager` | P1 |
| **异常邮件通知** | 异常时发送邮件，含错误详情和上下文 | P1 |
| **Punch Cards + 日常任务** | 扫描并完成更多任务 | P2 |
| **反检测增强** | 指纹伪装、行为随机化 | P2 |

---

## 三、总体策略：渐进式重构

> 不推倒重来，以现有 `WindowsPCServer` 的搜索能力为基石，逐步叠加新能力。

```
Phase 0: 基础重构（解耦、配置、日志）
    ↓
Phase 1: Dashboard 接入（读状态、领积分）
    ↓
Phase 2: Daily Set 自动化（核心收益来源）
    ↓
Phase 3: 任务体系扩展（Punch Cards、日常任务）
    ↓
Phase 4: 工程化打磨（反检测、监控、多账户）
```

### Phase 2：Daily Set 自动化（预计 3-4 天）

**目标**：自动完成每日 3 项 Daily Set 任务，这是 Rewards 的核心收益来源。

#### 任务 2.1：任务扫描器

| 项 | 内容 |
|-----|------|
| **改动范围** | 新增 `DailySetScanner` |
| **具体工作** | 1. 导航到积分赚取页面<br>2. 点击"每日连签活动"卡片打开弹窗<br>3. 扫描弹窗中的 3 项任务<br>4. 提取每项任务的：标题、积分、状态（已完成/未完成）、链接<br>5. 关闭弹窗 |
| **验收标准** | 能准确识别当天的 3 项任务及各自状态 |
| **风险** | 中（弹窗结构可能变化） |

#### 任务 2.2：任务类型识别器

| 项 | 内容 |
|-----|------|
| **改动范围** | 新增 `TaskTypeClassifier` |
| **具体工作** | 1. 根据任务链接 URL 中的参数识别类型：<br>   - `REWARDSQUIZ_DailySet_UrlOffer` → 搜索任务<br>   - `REWARDSQUIZ` → Quiz 任务<br>   - 含 `Poll` 关键字 → Poll 任务<br>   - 其他 → 点击/浏览任务<br>2. 根据任务标题做辅助判断（如含"投票""测验""搜索"） |
| **验收标准** | 当天 3 项任务的类型识别准确率 100% |
| **风险** | 低 |

#### 任务 2.3：搜索类任务处理器

| 项 | 内容 |
|-----|------|
| **改动范围** | 复用/扩展 `SearchService` |
| **具体工作** | 1. 点击任务链接跳转到 Bing 搜索页<br>2. 任务已完成（通常只需打开页面即可）<br>3. 若需要交互，模拟浏览行为（滚动、停留）<br>4. 返回 Dashboard 验证任务状态更新 |
| **验收标准** | 搜索类 Daily Set 可自动完成 |
| **风险** | 低 |

#### 任务 2.4：Poll 任务处理器

| 项 | 内容 |
|-----|------|
| **改动范围** | 新增 `PollTaskHandler` |
| **具体工作** | 1. 点击任务链接打开 Poll 页面<br>2. 扫描页面上的选项按钮<br>3. 随机选择其中一个选项<br>4. 点击提交<br>5. 验证积分到账 |
| **验收标准** | Poll 任务可自动完成 |
| **风险** | 低 |

#### 任务 2.5：Quiz 任务处理器

| 项 | 内容 |
|-----|------|
| **改动范围** | 新增 `QuizTaskHandler` |
| **具体工作** | 1. 点击任务链接打开 Quiz 页面<br>2. 检测题目类型（单选/多选/This or That）<br>3. 随机选择一个答案（即使答错也有积分）<br>4. 检测是否有多道题目，循环答题<br>5. 完成后的"继续"按钮自动点击<br>6. 支持答案缓存：若之前做过相同题目，尝试使用历史答案<br>7. 答错后将正确答案入库（通过页面反馈识别） |
| **验收标准** | Quiz 任务可自动完成，答案库逐渐积累 |
| **风险** | 中（Quiz 页面形式多样，需处理多种布局） |

#### 任务 2.6：点击/浏览类任务处理器

| 项 | 内容 |
|-----|------|
| **改动范围** | 新增 `ClickTaskHandler` |
| **具体工作** | 1. 点击任务链接<br>2. 在新页面停留随机时间（5-15 秒）<br>3. 模拟页面滚动<br>4. 若页面有"完成"按钮则点击<br>5. 关闭标签页返回 Dashboard |
| **验收标准** | 点击类任务可自动完成 |
| **风险** | 低 |

### Phase 4：工程化打磨（预计 3-4 天）

**目标**：提升稳定性、可维护性、反检测能力。

#### 任务 4.1：反检测增强

| 项 | 内容 |
|-----|------|
| **改动范围** | `EdgeDriverFactory` + 行为模拟 |
| **具体工作** | 1. 添加 `--disable-blink-features=AutomationControlled`<br>2. 添加 `--disable-web-security`（测试环境）<br>3. 修改 `navigator.webdriver` 为 `undefined`<br>4. 模拟真实鼠标移动轨迹（非瞬移点击）<br>5. 每次操作间隔随机化（基于正态分布）<br>6. 搜索时间窗口随机偏移（避免每天同一时间执行） |
| **验收标准** | 通过 `bot.sannysoft.com` 检测 |
| **风险** | 低 |

#### 任务 4.2：异常恢复机制

| 项 | 内容 |
|-----|------|
| **改动范围** | 全局异常处理 + 重试策略 |
| **具体工作** | 1. 任务级别重试：失败自动重试 3 次<br>2. 浏览器崩溃恢复：捕获异常后重启 Driver<br>3. 登录过期处理：检测登录页，暂停等待人工介入<br>4. 页面加载超时：设置显式等待，超时后跳过任务<br>5. 断点续传：记录执行进度到数据库，崩溃后恢复 |
| **验收标准** | 单任务失败不影响其他任务；浏览器崩溃可自愈 |
| **风险** | 中 |

#### 任务 4.2：异常邮件通知（用户明确要求）

| 项 | 内容 |
|-----|------|
| **改动范围** | 新增 `EmailNotificationService` + 配置扩展 |
